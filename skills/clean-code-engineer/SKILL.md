# Clean Code Engineer — Стандарт написания кода

Используй этот скилл при написании любого кода, скриптов, ботов, сайтов или конфигураций.

## 1. Главный принцип: «Сделал → Проверил → Работает с первого раза»
- Никогда не отдавай пользователю непроверенный код или сырой шаблон с заглушками `TODO`.
- После написания или правки кода **всегда** выполняй быструю верификацию:
  - **Java:** компиляция через `./scripts/build.sh` (или `javac`).
  - **Python:** проверка синтаксиса и импортов (`python3 -m py_compile` или тестовый прогон).
  - **TypeScript / React / Remotion:** проверка типов (`npx tsc --noEmit`) или рендер тестового кадра.
  - **Bash:** `bash -n script.sh`, заголовок `#!/usr/bin/env bash` и `set -euo pipefail`.
  - **YAML / JSON:** валидация парсером (`python3 -c "import yaml; yaml.safe_load(open('...'))"`), чтобы ни одна опечатка в отступах не сломала плагин при загрузке.

## 2. Защита от типичных багов
1. **Обработка граничных случаев:**
   - Всегда проверяй `null` / `None`, пустые списки, оффлайн-игроков, переполненный инвентарь, отрицательные суммы и отсутствие прав.
2. **Никаких интерактивных зависаний в CLI:**
   - При вызове внешних утилит или API избегай команд, которые ждут ввода с `/dev/tty` без таймаута. Используй неинтерактивные флаги (`--yes`, `--noconfirm`, `-o StrictHostKeyChecking=accept-new`) или прямые HTTP-запросы через `urllib`/`curl`.
3. **Безопасность и чистота репозитория:**
   - Не оставляй временные файлы в корне проекта (используй `/tmp` для одноразовых проверок).
   - Сохраняй существующие комментарии и форматирование в чужих файлах.
