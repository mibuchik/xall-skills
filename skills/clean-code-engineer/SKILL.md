# Clean Code Engineer — Стандарт написания кода

Используй этот скилл при написании и доработке любого кода, скриптов, ботов, десктопных и веб-приложений.

## 1. Главный принцип: «Сделал → Проверил → Работает с первого раза»
- Никогда не отдавай непроверенный код или сырой шаблон с заглушками `TODO` / `pass`.
- После любой правки **всегда** выполняй быструю верификацию:
  - **TypeScript / React / Electron:** `tsc --noEmit`, тесты и production-сборка.
  - **Python:** `ruff check` / `python3 -m py_compile` и `pytest`.
  - **Java:** `./gradlew build` / `mvn test` (или `javac --release 21`).
  - **Go / Rust:** `go test -race ./...` / `cargo clippy && cargo test`.
  - **Bash:** `bash -n script.sh`, `#!/usr/bin/env bash` и `set -euo pipefail`.
  - **YAML / JSON:** валидация парсером до деплоя/перезапуска.

## 2. Защита от типичных багов
1. **Обработка граничных случаев:** проверяй `null`/`None`/`undefined`, пустые коллекции, некорректные диапазоны (отрицательные суммы, `0`, переполнения), отсутствие прав доступа и обрывы сети.
2. **Никаких интерактивных зависаний в CLI:** передавай неинтерактивные флаги и явные таймауты для всех внешних команд и HTTP-запросов.
3. **Потокобезопасность и очистка ресурсов:** закрывай файлы, сокеты, слушатели событий и дочерние процессы в `finally`/`defer`/context manager.
4. **Безопасные границы:** никаких хардкод-путей пользователя (`/home/...`), секретов в коде, shell-инъекций и path traversal (`../`).

## 3. Архитектурная чистота
- Делай модули глубокими: компактный, понятный интерфейс снаружи и чёткая инкапсуляция деталей внутри.
- Не плоди «мёртвый код», закомментированные куски старых попыток и неиспользуемые импорты.
- Исправляй первопричину бага, а не маскируй симптом пустым `try/catch` или `sleep()`.
