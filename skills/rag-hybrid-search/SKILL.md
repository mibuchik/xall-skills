# RAG Hybrid Search

Построение точного RAG: умный чанкинг с метаданными, гибридный поиск (BM25 + dense embeddings + RRF), реранкинг и проверяемые цитаты.

## Когда применять
- Поиск по кодовой базе, документации, базам знаний и корпоративным PDF/Markdown
- Повышение recall@k и устранение галлюцинаций в RAG-пайплайнах

## Рабочий протокол
1. Чанкуй по смысловой структуре (заголовки Markdown, AST функций/классов, абзацы с небольшим overlap) и прикрепляй метаданные (путь, заголовок, дата, версия).
2. Комбинируй лексический поиск (BM25/FTS5 — идеален для точных идентификаторов и кодов ошибок) с векторным поиском через Reciprocal Rank Fusion (RRF).
3. Добавь этап cross-encoder reranking для сужения топ-30 кандидатов до топ-5–8 максимально релевантных фрагментов.
4. Оценивай retrieval отдельно от генерации: измеряй Recall@5, MRR/NDCG на контрольных вопросах до настройки LLM.
5. Требуй от генератора опираться строго на найденные фрагменты, указывать источники и честно говорить «в базе нет данных» при низком скоре.

## Чеклист качества
- [ ] Точные имена функций, тикетов и флагов находятся лексической веткой, а не теряются в эмбеддингах
- [ ] Измеряются отдельно метрики retrieval (Recall@k) и faithfulness ответа
- [ ] Индекс обновляется инкрементально при изменении файлов без полной переиндексации

## Антипаттерны (чего избегать)
- Резать код и таблицы фиксированными кусками по 500 символов посреди функции
- Класть в контекст 30 сырых чанков без реранкинга («lost in the middle»)

## Верификация перед завершением
Прогони набор из 20+ контрольных вопросов и замерь Recall@5 и долю неподтверждённых утверждений.
