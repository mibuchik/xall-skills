# Monorepo Architecture

Организация монорепозиториев (Bun/pnpm/Turborepo/Cargo): чистый граф пакетов, инкрементальный кэш сборок и контроль границ импортов.

## Когда применять
- Настройка или оздоровление монорепозитория с несколькими приложениями и shared-пакетами
- Ускорение медленных сборок, устранение циклических зависимостей и дублей версий

## Рабочий протокол
1. Построй строгий ациклический граф: `apps/*` зависят от `packages/*`, базовые утилиты не зависят от UI/инфраструктуры.
2. Вынеси общие конфиги (`tsconfig.base.json`, линтеры, форматтеры) в корень или внутренний пакет.
3. Настрой явный граф задач (`build` -> `typecheck` -> `test`) с точными `inputs`/`outputs` для кэширования.
4. Синхронизируй версии критических runtime-зависимостей (React, TypeScript, Zod) по всему воркспейсу.
5. В CI запускай проверки только для затронутых пакетов (`--filter=...[origin/main]`), оставляя полный прогон для `main`.

## Чеклист качества
- [ ] Отсутствуют относительные импорты в обход публичного `exports` другого пакета (`../../other-pkg/src`)
- [ ] Повторный запуск сборки без изменений попадает в кэш за миллисекунды
- [ ] Чистый клон собирается одной командой из корня без ручных шагов

## Антипаттерны (чего избегать)
- Пакет `packages/shared`, превратившийся в свалку со всеми зависимостями проекта
- Разные версии одной библиотеки в соседних пакетах, ломающие singleton-контексты

## Верификация перед завершением
Запусти чистую сборку всех пакетов, проверь отсутствие циклов и прогони кэш-хит повторным запуском.
