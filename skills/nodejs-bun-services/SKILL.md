# Nodejs Bun Services

Высокопроизводительные backend-сервисы на Bun и Node.js: Web Streams, graceful shutdown (`SIGTERM`), строгая валидация схем и контроль памяти.

## Когда применять
- Разработка HTTP/CLI/worker сервисов на Bun или Node.js 22+ на TypeScript
- Настройка graceful shutdown, стриминга, роутинга и обработки неперехваченных ошибок

## Рабочий протокол
1. Используй стандартные Web API (`fetch`, `AbortSignal.timeout`, `ReadableStream`, `URL`, `crypto.randomUUID`) для переносимости между Bun и Node.
2. Валидируй каждый внешний вход (`zod`/`valibot`) и сразу ограничивай максимальный размер тела запроса.
3. Реализуй graceful shutdown по `SIGINT`/`SIGTERM`: перестань принимать новые запросы, дождись активных в пределах таймаута, закрой пулы БД.
4. Не блокируй event loop синхронными `fs.*Sync` на горячем пути обработки запросов.
5. Используй структурное логирование (JSON) с уровнем логов и контекстом запроса, без секретов в логах.

## Чеклист качества
- [ ] У каждого `fetch` есть `AbortSignal.timeout(...)` или прокинутый сигнал отмены
- [ ] Процесс корректно завершается по `SIGTERM` с кодом 0 без зависших хендлов
- [ ] Ошибки `unhandledRejection` логируются и переводят сервис в безопасное состояние

## Антипаттерны (чего избегать)
- Читать весь большой файл или тело ответа в память целиком вместо потоковой обработки
- Хранить сессии и состояние в глобальном объекте процесса при горизонтальном масштабировании

## Верификация перед завершением
Прогони юнит/интеграционные тесты и проверь graceful shutdown под активным соединением.
