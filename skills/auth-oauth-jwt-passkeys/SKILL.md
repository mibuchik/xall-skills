# Auth Oauth JWT Passkeys

Безопасная аутентификация и авторизация: короткоживущие JWT + ротация refresh-токенов, HttpOnly cookie, OAuth2 PKCE, Passkeys и RBAC/ABAC.

## Когда применять
- Реализация входа, сессий, OAuth2/OIDC, WebAuthn/Passkeys и проверки прав доступа
- Аудит существующей авторизации на IDOR, CSRF и утечку токенов

## Рабочий протокол
1. Для браузерных клиентов предпочитай серверные сессии или токены в `HttpOnly; Secure; SameSite=Lax` cookie — не клади долгоживущие токены в `localStorage`.
2. Если используешь JWT: короткий срок access-токена (5–15 мин), строгая проверка `alg`, `iss`, `aud`, `exp`, ротация refresh-токена с детектом повторного использования.
3. Для OAuth2 всегда используй Authorization Code Flow + PKCE (`S256`) + проверку `state` и `nonce`.
4. Пароли хэшируй только через Argon2id (или scrypt/bcrypt с актуальными параметрами) и сравнивай секреты через `timingSafeEqual`.
5. Проверяй авторизацию (ownership / RBAC) на КАЖДОМ эндпоинте и на уровне выборки объекта (защита от IDOR).

## Чеклист качества
- [ ] Нигде нет `alg: none` или автоматического выбора алгоритма из заголовка JWT
- [ ] Права проверяются на сервере, а не только скрытием кнопок в UI
- [ ] Все auth-эндпоинты защищены rate limiting и не утекают лишнюю информацию в сообщениях ошибок

## Антипаттерны (чего избегать)
- Доверять `user_id` из тела запроса вместо идентификатора из проверенной сессии
- Хранить refresh-токены в открытом виде в БД вместо SHA-256 хэша

## Верификация перед завершением
Напиши негативные тесты: истёкший токен, чужой ресурс (IDOR), подмена алгоритма, повторный refresh.
