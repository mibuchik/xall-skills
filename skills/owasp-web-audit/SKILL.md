# OWASP Web Audit

Структурированный аудит веб-приложений и API по OWASP Top 10 / ASVS: контроль доступа, SSRF, инъекции, небезопасные дефолты и отчёт с PoC.

## Когда применять
- Аудит безопасности нового или существующего веб-сервиса, API или десктопного клиента
- Поиск уязвимостей контроля доступа (IDOR/BOLA), SSRF, XSS, CSRF и утечек данных

## Рабочий протокол
1. Начни с карты поверхности атаки: все точки входа (HTTP, WebSocket, IPC, файлы, CLI), границы доверия и привилегированные операции.
2. Проверь контроль доступа (Broken Access Control / BOLA / BFLA): можно ли прочитать/изменить чужую сущность по ID или вызвать админ-метод без роли.
3. Проверь инъекции (SQL, shell/exec, template, path traversal `../`) и SSRF (запросы к `127.0.0.1`, `169.254.169.254`, внутренним портам).
4. Проверь fail-open дефолты: захардкоженные fallback-секреты, открытый CORS `*` с credentials, включённый debug/stacktrace, слабые права на файлы.
5. Для каждой находки фиксируй: серьёзность, точный файл/строку, сценарий эксплуатации и минимальный безопасный патч.

## Чеклист качества
- [ ] Все маршруты имеют явную проверку прав по принципу default-deny
- [ ] Внешние пути и URL валидируются строгим allowlist до использования
- [ ] Исправление подтверждено негативным security-тестом

## Антипаттерны (чего избегать)
- Делать поверхностный чеклист без реального чтения потоков данных source -> sink
- Репортить теоретический шум без подтверждения достижимости в коде

## Верификация перед завершением
Прогони негативные security-тесты на каждую закрытую находку и убедись, что основной функционал не сломан.
