# Web Accessibility WCAG

Доступность интерфейсов по WCAG 2.2 AA: семантический HTML, полная клавиатурная навигация, WAI-ARIA combobox/dialog и контрастность.

## Когда применять
- Создание интерактивных виджетов (меню, модалки, табы, комбобоксы, формы) и a11y-аудит
- Проверка контрастности, фокуса и поддержки скринридеров

## Рабочий протокол
1. Сначала используй нативную семантику (`<button>`, `<a>`, `<dialog>`, `<label>`, `<nav>`, `<main>`) — ARIA только там, где нет нативного элемента.
2. Обеспечь полный проход клавиатурой: `Tab`, `Shift+Tab`, `Enter`, `Space`, `Escape`, стрелки в списках и меню.
3. Для автодополнения и палитр команд реализуй виртуальный фокус (`role='combobox'` + `aria-activedescendant`), не уводя фокус из поля ввода.
4. Проверяй контраст: минимум 4.5:1 для обычного текста, 3:1 для крупного текста и границ UI-элементов.
5. Уважайте `prefers-reduced-motion`: отключай пространственные перелёты и параллакс при запросе сниженного движения.

## Чеклист качества
- [ ] У каждой icon-only кнопки есть `aria-label` (и `title` при необходимости)
- [ ] Видимый `:focus-visible` контур никогда не убирается без явной замены
- [ ] Модальные диалоги возвращают фокус на триггер после закрытия

## Антипаттерны (чего избегать)
- Кликабельные `<div onClick>` без роли, `tabIndex` и клавиатурного обработчика
- Глобальный `outline: none` без стилей `:focus-visible`

## Верификация перед завершением
Пройди ключевой сценарий целиком без мыши (только клавиатурой) и проверь a11y-дерево в DevTools.
