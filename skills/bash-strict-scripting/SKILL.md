# Bash Strict Scripting

Надёжные Bash-скрипты продакшен-уровня: `set -euo pipefail`, безопасное экранирование, `trap` на cleanup, временные файлы и проверка ShellCheck.

## Когда применять
- Написание и ревью `.sh` скриптов автоматизации, деплоя, бэкапов и пайплайнов
- Исправление багов с пробелами в путях, тихими ошибками пайпов и осиротевшими tmp-файлами

## Рабочий протокол
1. Начинай каждый скрипт с `#!/usr/bin/env bash` и `set -euo pipefail` (плюс `IFS=$'\n\t'`), чтобы любая ошибка в команде или пайпе останавливала выполнение.
2. Всегда бери расширения переменных в двойные кавычки (`"$var"`, `"${arr[@]}"`) и используй `[[ ... ]]` вместо `[ ... ]`.
3. Создавай временные файлы/папки через `mktemp -d` и гарантированно удаляй их через `trap 'rm -rf "$TMPDIR"' EXIT`.
4. Для перебора файлов с любыми именами используй `find ... -print0 | while IFS= read -r -d '' f; do ...` — никогда `for f in $(ls ...)`.
5. Если логика сложнее 150 строк, со словарями/JSON/сетью — переводи задачу на Python вместо хрупкого Bash.

## Чеклист качества
- [ ] `bash -n script.sh` и `shellcheck script.sh` проходят без ошибок
- [ ] Нет неэкранированных `$var`, небезопасных `rm -rf $DIR/*` и `eval` на внешнем вводе
- [ ] Скрипт идемпотентен и поддерживает `--help` / понятный stderr при нехватке аргументов

## Антипаттерны (чего избегать)
- Писать `rm -rf $TARGET_DIR/` без проверки `${TARGET_DIR:?}` (при пустой переменной удалит корень!)
- Использовать `pkill -f` с шаблоном, совпадающим с командной строкой самого запускающего bash-процесса

## Верификация перед завершением
Прогони `bash -n`, `shellcheck` и тестовый запуск на директории с пробелами в имени.
