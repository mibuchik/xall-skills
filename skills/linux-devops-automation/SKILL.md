# Linux & DevOps Automation

Универсальный стандарт системного администрирования Linux-рабочих станций и серверов (Arch, Debian/Ubuntu, Fedora) без лишних `sudo`-хаков и поломок окружения.

## Когда применять
- Установка и обновление CLI-инструментов, настройка `PATH`, профилей shell и локальных сервисов.
- Диагностика занятых сетевых портов, зависших процессов, дисков, прав доступа и переменных окружения.
- Автоматизация Git, Git LFS, GitHub CLI (`gh`) и локальных воркфлоу.

## Рабочий протокол
1. **Проверяй среду перед действием:** сначала определи дистрибутив (`/etc/os-release`), архитектуру (`uname -m`), графическую сессию (`$XDG_SESSION_TYPE`: Wayland vs X11) и наличие нужных бинарников (`command -v`).
2. **Установка CLI без `sudo`:** для пользовательских инструментов предпочитай официальные статические бинарники или менеджеры версий (`~/.local/bin`, `uv`, `bun`, `rustup`), добавляя `~/.local/bin` в `PATH` и сверяя контрольные суммы SHA-256.
3. **Буфер обмена и открытия:** на Wayland используй `wl-copy` / `wl-paste`, на X11 — `xclip -selection clipboard` / `xsel`, для ссылок — `xdg-open`.
4. **Процессы и порты:** проверяй слушающие сокеты через `ss -tulpn` (или `lsof -i :PORT`), завершай процессы мягко (`SIGTERM`, затем при необходимости `SIGKILL`) по точному PID — избегай слепого `pkill -f`, который может убить родительский shell.
5. **Бэкап перед правкой конфигов:** перед редактированием системных/пользовательских конфигов делай резервную копию (`.bak`) и валидируй синтаксис целевой утилитой перед перезапуском сервиса.
6. **Git и GitHub CLI:** держи чистый `.gitignore`, крупные бинарники переноси в Git LFS (`git lfs track`), проверяй `gh auth status` до автоматизации PR/репозиториев.

## Чеклист качества
- [ ] Скрипты не хардкодят абсолютные пути `/home/<user>` (используют `$HOME` или `${XDG_CONFIG_HOME:-$HOME/.config}`)
- [ ] Секретные ключи и конфиги токенов имеют права `0600` (каталоги — `0700`)
- [ ] Не оставлены фоновые процессы без контроля (`systemd --user` вместо `nohup ... &`)

## Антипаттерны (чего избегать)
- Запускать `curl ... | sudo bash` без проверки источника и содержимого скрипта
- Использовать `chmod 777` вместо точечных прав владельца/группы
- Ставить пользовательские Python/Node пакеты глобально через `sudo pip` / `sudo npm`

## Верификация перед завершением
Проверь установленную версию (`<tool> --version`), права файлов (`ls -la`), статус сервисов (`systemctl --user status`) и отсутствие лишних открытых портов (`ss -tulpn`).
