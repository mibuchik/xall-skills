# Vite Bundle Optimizer

Оптимизация сборки и времени загрузки Vite/Rollup: анализ чанков, ленивая подгрузка тяжёлых зависимостей, tree-shaking и ассеты.

## Когда применять
- Раздутый JS-бандл, медленный cold start, предупреждения chunk size > 500kB в Vite
- Настройка code-splitting для редакторов, чартов, санитайзеров и иконок

## Рабочий протокол
1. Сними карту бандла (`vite-bundle-visualizer` или разбор `dist/assets/*.js` gzip-размеров) и найди топ-5 самых тяжёлых модулей.
2. Вынеси тяжёлые редко используемые модули (графики, подсветка синтаксиса, Markdown/DOMPurify, PDF) в динамические `import()` / `React.lazy`.
3. Проверь импорты библиотек: избегай barrel-файлов, мешающих tree-shaking, и заменяй монструозные зависимости на компактные аналоги.
4. Оптимизируй ассеты: SVG оптимизируй, растр переводи в WebP/AVIF с явными `width`/`height` против CLS.
5. Зафиксируй бюджет бандла и сверяй gzip-размеры после каждого крупного обновления.

## Чеклист качества
- [ ] Начальный entry-чанк минимален и не тянет в себя оффлайн-виджеты с других вкладок
- [ ] Отсутствуют дубли одной библиотеки в разных версиях внутри бандла
- [ ] CSS и JS сжимаются эффективно, а source maps не протекают в публичный прод без нужды

## Антипаттерны (чего избегать)
- Импортировать целиком `lodash` или весь пакет иконок вместо точечных ESM-импортов
- Дробить чанки на 50 крошечных файлов по 2 KB, создавая сетевой overhead

## Верификация перед завершением
Выполни `vite build`, сравни размеры чанков (raw + gzip) до и после, проверь работу lazy-роутов.
