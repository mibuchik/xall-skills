# Sqlite Local First

Надёжный SQLite для десктопных и local-first приложений: режим WAL, `busy_timeout`, `PRAGMA foreign_keys`, FTS5 поиск и атомарные бэкапы.

## Когда применять
- Хранение локальных данных чатов, кешей, индексов или состояния в SQLite
- Устранение `SQLITE_BUSY`, ускорение вставок и настройка полнотекстового поиска FTS5

## Рабочий протокол
1. При каждом открытии соединения включай обязательный набор PRAGMA: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`, `temp_store=MEMORY`.
2. Группируй массовые вставки в одну явную транзакцию (`BEGIN IMMEDIATE ... COMMIT`) — это ускоряет запись в сотни раз.
3. Храни схему через версионированные миграции (`PRAGMA user_version`) с идемпотентным применением при старте.
4. Для мгновенного локального поиска используй виртуальные таблицы `FTS5` с триггерами синхронизации.
5. Выполняй бэкапы через `VACUUM INTO` или Online Backup API, а не простым `cp` открытого файла БД.

## Чеклист качества
- [ ] Права на файл БД с пользовательскими данными ограничены (`0600`)
- [ ] Все SQL-запросы строго параметризованы (`?` / `:name`), без интерполяции строк
- [ ] Нет длительных открытых транзакций чтения, блокирующих checkpoint WAL

## Антипаттерны (чего избегать)
- Делать 1000 одиночных `INSERT` в режиме autocommit без транзакции
- Забывать `PRAGMA foreign_keys = ON` (в SQLite оно выключено по умолчанию!)

## Верификация перед завершением
Протестируй конкурентные чтение+запись, повторную миграцию и целостность через `PRAGMA integrity_check`.
