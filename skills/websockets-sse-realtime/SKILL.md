# Websockets SSE Realtime

Надёжный real-time стриминг (SSE и WebSockets): переподключение с backoff, `Last-Event-ID`, heartbeat, контроль буферов и чистое закрытие.

## Когда применять
- Стриминг ответов LLM (SSE), живые логи, чаты, уведомления и совместное редактирование
- Устранение «зависших» соединений, потери чанков и дублей после реконнекта

## Рабочий протокол
1. Выбирай SSE для однонаправленного стриминга (LLM токены, логи, уведомления) — оно проще, дружит с HTTP/2 и прокси; WebSockets — для двунаправленного low-latency.
2. Отправляй периодический heartbeat/comment (`: ping\n\n` каждые 15–25s), чтобы Nginx/NAT не обрывал тихие соединения.
3. Отключай буферизацию на прокси (`X-Accel-Buffering: no`, `Cache-Control: no-cache`) и корректно собирай чанки, разрезанные посреди UTF-8 символа (`TextDecoder({ stream: true })`).
4. На клиенте реализуй реконнект с exponential backoff + jitter и передачу `Last-Event-ID` для дочитывания без пропусков.
5. При закрытии/таймауте клиента гарантированно снимай подписки и освобождай серверные буферы.

## Чеклист качества
- [ ] Парсер SSE корректно склеивает неполные строки и многобайтовые UTF-8 символы между чанками
- [ ] Есть кнопка/механизм отмены стрима (`AbortController`), корректно завершающий генерацию на сервере
- [ ] Медленный клиент не вызывает бесконечный рост памяти сервера (bounded queue / drop / disconnect)

## Антипаттерны (чего избегать)
- Парсить `chunk.split('\n')` без буфера остатка — неизбежно ломает JSON на границах пакетов
- Бесконечный мгновенный реконнект в цикле `while(true)` без задержки при падении сервера

## Верификация перед завершением
Протестируй разрезание SSE-сообщения по 1–3 байта, кириллицу/эмодзи и обрыв на середине потока.
