# LORA QLORA Finetuning

Практика дообучения LLM (SFT, LoRA/QLoRA, DPO+NLL): чистая подготовка данных, защита от забывания, настройка rank/LR и контроль по валидации.

## Когда применять
- Дообучение локальных моделей (SFT, Iterative DPO, LoRA/QLoRA) на PyTorch/Unsloth/TRL
- Отладка переобучения, деградации рассуждений, OOM VRAM и слияния адаптеров в BF16

## Рабочий протокол
1. Начни с аудита датасета: дедупликация, очистка утечек шаблона, проверка chat template и распределение длин токенов (маскируй loss на промпте!).
2. Подмешивай 10–25% качественного replay-микса из общих/кодовых задач, чтобы исключить катастрофическое забывание.
3. Для LoRA/QLoRA таргетируй все линейные проекции (`q,k,v,o,gate,up,down`), включай gradient checkpointing, cosine LR с warmup и логируй `grad_norm` + eval loss.
4. Для DPO на reasoning/code моделях добавляй вспомогательный NLL-терм (`rpo_alpha` / SFT loss на chosen), чтобы не проседала вероятность правильного решения.
5. Мержи адаптер в чистый BF16 на CPU/GPU с проверкой контрольных генераций и строго отделяй benchmark-выборки от train.

## Чеклист качества
- [ ] Chat template в обучении на 100% совпадает с темплейтом инференса (special tokens, `<think>`, EOS)
- [ ] Ни одна задача из eval/бенчмарков не попала в train (проверка дедупликацией)
- [ ] Чекпоинт проходит автоматический roll-forward gate на реальных задачах до замены продакшен-весов

## Антипаттерны (чего избегать)
- Обучать DPO без контроля деградации длины и без NLL-стабилизатора
- Оценивать успех только по падению train loss без независимого executable eval

## Верификация перед завершением
Проверь логи `loss`/`grad_norm`, протестируй merged-модель на контрольных промптах и независимом бенчмарке.
