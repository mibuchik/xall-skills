# Linux Hardening SSH

Базовое укрепление Linux-серверов и рабочих станций: SSH только по ключам Ed25519, nftables/UFW, минимальные открытые порты и изоляция сервисов.

## Когда применять
- Первичная настройка VPS/сервера Linux, аудит открытых портов и укрепление SSH
- Проверка экспозиции локальных сервисов (API, БД, Docker-порты) в сеть

## Рабочий протокол
1. Проверь все слушающие сокеты (`ss -tulpn`): локальные API/БД/админки должны слушать `127.0.0.1`, а не `0.0.0.0` (учти, что Docker по умолчанию пробрасывает `-p 8080:8080` на `0.0.0.0`, пиши `-p 127.0.0.1:8080:8080`!).
2. Укрепи SSH (`/etc/ssh/sshd_config.d/99-hardening.conf`): `PasswordAuthentication no`, `PermitRootLogin no`, ключи `ed25519`, тестируй `sshd -t` и проверяй вход во втором терминале ДО закрытия текущего!
3. Настрой файрвол (nftables/UFW): политика по умолчанию `deny incoming`, открыты только нужные порты (22/80/443).
4. Включай автоматические обновления безопасности и защиту от брутфорса (fail2ban / sshguard).
5. Изолируй сервисы в systemd директивами `NoNewPrivileges=yes`, `PrivateTmp=yes`, `ProtectSystem=strict` там, где это не мешает работе.

## Чеклист качества
- [ ] Нет случайно выставленных наружу портов БД, Redis, Docker daemon или локальных LLM-серверов
- [ ] Вход по паролю и под root по SSH отключён после подтверждения входа по ключу
- [ ] Файрвол активен и сохраняется после перезагрузки

## Антипаттерны (чего избегать)
- Перезапускать `sshd` без проверки `sshd -t` и без открытой резервной сессии
- Пробрасывать `-p 5432:5432` в Docker, думая, что UFW его заблокирует (iptables Docker обходит UFW!)

## Верификация перед завершением
Проверь `ss -tulpn`, статус файрвола и тест подключения с другого терминала.
