# Data Cleaning Dedup

Очистка и дедупликация текстовых и кодовых датасетов (JSONL): нормализация, точный + нечёткий MinHash/n-gram dedup, проверка контаминации бенчмарков.

## Когда применять
- Подготовка корпусов для SFT/DPO/RLVR, очистка скрапленных данных и удаление дублей
- Проверка отсутствия утечки тестовых бенчмарков (HumanEval, MBPP, SWE-bench) в обучающую выборку

## Рабочий протокол
1. Выполни первичный аудит JSONL: битые JSON-строки, пустые поля, экстремальные длины, кодировка UTF-8, распределение по источникам.
2. Удали точные дубли по SHA-256 нормализованного текста (пробелы, регистр/комментарии) и нечёткие дубли по 13-gram / MinHash LSH.
3. Проведи обязательный decontamination-проход против всех eval-бенчмарков (точное и n-gram пересечение промптов и решений).
4. Отфильтруй мусор: обрезанные ответы без закрытых блоков кода, зацикленные повторы фраз, нежелательные бренд-утечки и битый синтаксис (`ast.parse`).
5. Сохраняй подробный JSON-отчёт отбраковки: сколько строк удалено каждым правилом и почему.

## Чеклист качества
- [ ] Каждая строка выходного JSONL валидна и проходит проверку обязательных полей
- [ ] Доказано 0 пересечений с тестовыми бенчмарками (decontamination report)
- [ ] Сохранены исходные файлы (работаем в новый выходной файл, не затираем сырой корпус)

## Антипаттерны (чего избегать)
- Обучать модель на нефильтрованном дампе с 40% дублей и битым синтаксисом
- Пропускать decontamination и получать искусственно завышенные метрики

## Верификация перед завершением
Проверь отчёт фильтрации, валидность JSONL и ручную выборку 20 случайных записей глазами.
