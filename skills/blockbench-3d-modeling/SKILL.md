# Blockbench 3D Modeling

Моделирование и анимация в Blockbench (`.bbmodel`): чистая иерархия костей и пивотов, плотный pixel-consistent UV без растяжек, плавные циклы и валидация экспорта.

## Когда применять
- Создание или правка 3D-моделей, скелетов, текстур и анимаций в Blockbench (Bedrock/Java/ModelEngine/MythicMobs)
- Исправление Z-fighting, сломанных пивотов, кривого UV и визуальная проверка рендеров

## Рабочий протокол
1. Выстрой анатомическую иерархию костей (`root` -> `body` -> `head`/`arm_l`/`arm_r`/`leg_l`/`leg_r`) с пивотами ровно в реальных суставах вращения.
2. Соблюдай единую плотность текселей (texel density) по всей модели, избегай Z-fighting (разноси совпадающие грани на `0.01–0.05` или используй `inflate`).
3. Упаковывай UV без перекрытий (если не задумана зеркальность), оставляй чистые отступы и проверяй текстуру в 1:1 пиксельной чёткости.
4. Для анимаций (`idle`, `walk`, `attack`, `death`) используй плавные интерполяции (catmullrom/bezier), вторичное движение и проверяй бесшовность цикла (первый кадр == последний).
5. Валидируй модель и делай контакт-лист рендеров (front/back/side/iso + ключевые позы анимации) для визуальной проверки глазами.

## Чеклист качества
- [ ] Нет Z-fighting, оторванных конечностей в крайних позах и вывернутых граней
- [ ] Имена костей и анимаций чистые (`snake_case`, без пробелов и дублей)
- [ ] Экспорт (Bedrock geometry/animation или Java block JSON) проходит валидатор без предупреждений

## Антипаттерны (чего избегать)
- Оставлять пивот конечности в центре мира `[0,0,0]` — при вращении рука улетает по дуге
- Сдавать модель без визуальной проверки со всех ракурсов и в позах анимации

## Верификация перед завершением
Выполни валидацию `.bbmodel` и анимаций + просмотри рендеры со всех сторон и ключевых кадров.
