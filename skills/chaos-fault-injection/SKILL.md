# Chaos Fault Injection

Проверка отказоустойчивости (Chaos Engineering): контролируемая инъекция задержек, обрывов сети, отказов зависимостей и деградации диска.

## Когда применять
- Проверка graceful degradation, failover, ретраев и поведения UI/API при падении апстрима
- Тестирование очередей, таймаутов и восстановления после перезапуска узла

## Рабочий протокол
1. Определи steady-state гипотезу: какая метрика должна сохраняться при отказе конкретной зависимости.
2. Начни с минимального радиуса поражения (локальный/staging стенд) и заранее подготовь мгновенный abort-переключатель.
3. Поочерёдно инъецируй сбои: повышенная задержка (+2s), 500/503 ошибки, обрыв TCP/SSE посреди ответа, недоступность кэша/БД, заполнение диска.
4. Наблюдай за поведением: срабатывают ли таймауты, освобождаются ли слоты/блокировки, не падает ли весь процесс из-за второстепенного сервиса.
5. Преврати найденные слабые места в автоматические негативные интеграционные тесты.

## Чеклист качества
- [ ] Обрыв апстрима не вешает UI или event loop навечно (везде есть таймауты)
- [ ] Падение необязательной зависимости (кэш, аналитика, MCP) деградирует мягко
- [ ] После восстановления зависимости система сама возвращается в штатный режим без ручного рестарта

## Антипаттерны (чего избегать)
- Ломать несколько систем сразу, не понимая, какой именно сбой вызвал деградацию
- Проводить хаос-эксперименты без наблюдаемости и плана мгновенного отката

## Верификация перед завершением
Прогони негативные тесты (timeout, abort, 503, disconnect) и проверь чистоту освобождения ресурсов.
