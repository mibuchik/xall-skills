# Readme Open Source Polish

Полировка `README.md` для GitHub-репозиториев: ясное ценностное предложение в первом экране, живой скриншот/демо, 3-шаговая установка, архитектура и лицензия.

## Когда применять
- Создание или обновление `README.md` перед публикацией репозитория на GitHub
- Улучшение читаемости и первого впечатления от проекта

## Рабочий протокол
1. Первый экран: логотип/название, одно точное предложение «что делает проект и для кого» и визуал (скриншот/схема/короткий вывод CLI).
2. Сразу ниже — «Быстрый старт» (3–5 команд установки и запуска) с честными требованиями среды.
3. Добавь краткий обзор возможностей (конкретные факты, без пустого маркетингового хайпа), конфигурацию и структуру репозитория.
4. Вынеси команды разработки и тестов (`typecheck`, `test`, `build`) в отдельный раздел Contributing / Development.
5. Проверь, что в `README.md` нет битых относительных ссылок, личных путей (`/home/...`) и устаревших скриншотов.

## Чеклист качества
- [ ] Человек за 15 секунд понимает, зачем проект нужен и как его запустить
- [ ] Все пути к файлам и картинкам реально существуют в репозитории
- [ ] Нет маркетинговой воды и ложных обещаний несуществующих фич

## Антипаттерны (чего избегать)
- Начинать README со стены из 15 бейджей и 3 абзацев воды до объяснения сути проекта
- Оставлять шаблонные `TODO` и сломанные команды установки

## Верификация перед завершением
Проверь рендер Markdown, все локальные ссылки и запуск команд из секции Quickstart.
