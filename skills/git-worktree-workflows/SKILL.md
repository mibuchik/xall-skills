# Git Worktree Workflows

Мастерская работа с `git worktree` и историей: параллельная разработка и субагенты без stash-ада, чистые коммиты и безопасное восстановление через `reflog`.

## Когда применять
- Параллельная работа над несколькими задачами/ветками или изоляция субагентов через `git worktree`
- Аккуратный rebase, cherry-pick, bisect поиска регрессий и чистка веток

## Рабочий протокол
1. Создавай изолированные рабочие копии командой `git worktree add ../repo-feat -b feat/x main` — один `.git` объектник, нулевые конфликты файлов и сборок.
2. Проверяй активные worktree через `git worktree list` и чисто удаляй завершённые через `git worktree remove <path>` + `git worktree prune`.
3. Для поиска коммита, сломавшего тест, используй автоматический `git bisect start HEAD <good> && git bisect run <test-cmd>`.
4. Перед переписыванием истории (`rebase -i`, `reset`) проверяй `git status` и помни про `git reflog` для мгновенного отката; на публичные ветки делай только `--force-with-lease`, никогда слепой `--force`.
5. Держи коммиты атомарными с осмысленными сообщениями (`feat:`, `fix:`, `refactor:`, `test:`).

## Чеклист качества
- [ ] В рабочей копии нет незакоммиченных временных файлов и конфликтов перед слиянием
- [ ] Завершённые worktree аккуратно удалены и ветки синхронизированы
- [ ] `.gitignore` надёжно отсекает артефакты сборок, логи и `.env`

## Антипаттерны (чего избегать)
- Делать `git reset --hard` или `git clean -fdx` без проверки незакоммиченных файлов
- Хранить 10 незавершённых `git stash` вместо отдельных worktree/веток

## Верификация перед завершением
Проверь `git status`, `git worktree list` и `git log -n 5 --oneline`.
