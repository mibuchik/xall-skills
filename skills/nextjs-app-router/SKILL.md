# Nextjs App Router

Надёжная архитектура Next.js App Router: чёткая граница Server/Client Components, streaming Suspense, явное кэширование и безопасные Server Actions.

## Когда применять
- Разработка и отладка Next.js App Router, RSC, Server Actions, SSR и кеш-инвалидации
- Устранение ошибок гидратации и утечки серверного кода в клиентский бандл

## Рабочий протокол
1. Держи компоненты серверными по умолчанию; добавляй `'use client'` максимально низко в дереве — только на интерактивных листьях.
2. Защищай серверные модули (БД, секреты) импортом `server-only`, чтобы бандлер падал на сборке при случайном клиентском импорте.
3. Оборачивай независимые медленные запросы в `<Suspense>` границы вместо блокировки всей страницы одним `await`.
4. В Server Actions всегда перепроверяй аутентификацию/авторизацию и валидируй входные данные схемой — относись к ним как к публичным POST-эндпоинтам.
5. Управляй кэшем явно (`revalidateTag` / `revalidatePath` / `cache: 'no-store'`) и документируй политику свежести данных.

## Чеклист качества
- [ ] Ноль предупреждений hydration mismatch в консоли браузера
- [ ] Секреты без префикса `NEXT_PUBLIC_` не попадают в клиентский JS
- [ ] Все Server Actions возвращают структурированные ошибки валидации без необработанных исключений

## Антипаттерны (чего избегать)
- Ставить `'use client'` на корневой `layout.tsx` и тащить весь граф на клиент
- Выполнять последовательный waterfall из `await` вместо `Promise.all` или параллельных RSC

## Верификация перед завершением
Выполни `next build`, проверь размеры route-чанков и прогони SSR/гидратацию без ошибок.
