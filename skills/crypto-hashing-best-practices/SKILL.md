# Crypto Hashing Best Practices

Безопасная прикладная криптография без самописных шифров: Argon2id для паролей, AES-256-GCM / ChaCha20-Poly1305, CSPRNG и constant-time сравнения.

## Когда применять
- Хэширование паролей, шифрование данных, подпись токенов/вебхуков (HMAC) и генерация ключей
- Аудит криптографических примитивов на устаревшие алгоритмы (MD5/SHA1/ECB) и повтор nonce

## Рабочий протокол
1. Никогда не изобретай собственные криптоалгоритмы — используй стандартные проверенные библиотеки (Node `node:crypto`, Web Crypto API, Python `cryptography`/`argon2-cffi`, libsodium).
2. Пароли: только `Argon2id` (или `scrypt`/`bcrypt`) с уникальной случайной солью; НИКОГДА `MD5`, `SHA-1` или голый `SHA-256`.
3. Симметричное шифрование: только AEAD (`AES-256-GCM` или `XChaCha20-Poly1305`) с уникальным случайным nonce на КАЖДОЕ шифрование — повтор nonce в GCM фатален!
4. Подпись вебхуков и целостность: `HMAC-SHA256` и строгое сравнение через `timingSafeEqual` / `hmac.compare_digest`.
5. Случайные токены и ID сессий: только CSPRNG (`crypto.randomBytes`, `secrets.token_urlsafe`), никогда `Math.random()` или `random.random()`.

## Чеклист качества
- [ ] Отсутствуют `Math.random()`, `ECB`, `MD5`/`SHA1` в контексте безопасности
- [ ] Каждый шифротекст хранит версию схемы, уникальный nonce и auth tag
- [ ] Сравнение подписей и API-ключей выполняется за константное время

## Антипаттерны (чего избегать)
- Использовать фиксированный IV/nonce `0000...` или производный от предсказуемого счётчика без контроля
- Шифровать без аутентификации (CBC без HMAC -> уязвимость padding oracle)

## Верификация перед завершением
Напиши тесты на round-trip шифрование, уникальность nonce и отклонение подделанного 1 байта шифротекста/тега.
