# Scraping Ethics Parsers

Надёжный и этичный парсинг веб-документов и открытых API: уважение `robots.txt` и rate-limits, устойчивые селекторы, кэширование и никогда не обходить CAPTCHA/авторизацию.

## Когда применять
- Извлечение структурированных данных из открытой документации, RSS/Atom, JSON API и HTML-страниц
- Устранение хрупких парсеров, кодировок и повторных скачиваний

## Рабочий протокол
1. Сначала проверь наличие официального API, RSS/Atom, sitemap или статических JSON/Markdown — это на порядок стабильнее и вежливее HTML-скрейпинга.
2. Соблюдай `robots.txt`, выставляй честный `User-Agent`, ограничивай частоту запросов и обрабатывай `429 Retry-After` с экспоненциальным backoff; НИКОГДА не обходи CAPTCHA, антибот-проверки или закрытый доступ.
3. Кэшируй сырые ответы локально (ETag / If-Modified-Since) и отделяй фазу скачивания (fetch) от фазы разбора (parse), чтобы отлаживать парсер оффлайн.
4. Пиши парсер на реальном HTML-парсере (`BeautifulSoup`/`lxml`/`selectolax`/`cheerio`) с опорой на семантические атрибуты, а не на хрупкие `div > div:nth-child(4)` или регэкспы по HTML.
5. Валидируй каждую извлечённую запись схемой (Pydantic/Zod) и логируй долю пустых полей как сигнал смены вёрстки.

## Чеклист качества
- [ ] Есть таймаут, лимит ретраев и задержка между запросами
- [ ] Фаза парсинга покрыта юнит-тестами на сохранённых HTML-фикстурах
- [ ] Уважает `robots.txt` и не пытается обходить защитные экраны

## Антипаттерны (чего избегать)
- Парсить вложенный HTML регулярными выражениями
- Перекачивать 1000 страниц заново на каждую правку одного CSS-селектора

## Верификация перед завершением
Запусти тесты парсера на локальных фикстурах (включая неполные карточки и UTF-8 символы).
