# Discord Bot Architecture

Надёжные Discord-боты (discord.py / discord.js): slash-команды, обязательный `defer()` за 3 секунды, минимальные Intents, шардинг и обработка rate-limits.

## Когда применять
- Разработка Discord-ботов, slash-команд, интерактивных кнопок/модалок и интеграций с серверами
- Устранение ошибок `Unknown Interaction` (таймаут 3с), проблем с правами и синхронизацией команд

## Рабочий протокол
1. Для любой операции дольше ~500ms вызывай `defer()` в самом начале хендлера (Discord жёстко обрывает необработанный interaction через 3 секунды!), затем отвечай через `followup`.
2. Запрашивай только реально нужные Gateway Intents — не включай привилегированный `Message Content` без прямой необходимости.
3. Организуй код в Cogs / модули команд с явной проверкой прав (`default_member_permissions`, `guild_only`, ролевые проверки на сервере).
4. Для кнопок и селектов делай persistent views (стабильные `custom_id`), переживающие рестарт бота.
5. Соблюдай лимиты Discord: Embed <= 6000 символов (description <= 4096), текст <= 2000, не спамь глобальным `tree.sync()` на каждый рестарт.

## Чеклист качества
- [ ] Долгие команды вызывают `defer()` сразу и всегда завершают ответ даже при ошибке (`try/finally`)
- [ ] Синхронизация slash-команд выполняется осознанно (на тестовой гильдии или по админ-команде), не сжигая rate limit
- [ ] Ошибки прав (`Forbidden`) обрабатываются мягко с понятным ephemeral-сообщением

## Антипаттерны (чего избегать)
- Вызывать `tree.sync()` на каждый `on_ready()` (повторные реконнекты быстро ловят 429)
- Отображать внутренние traceback-и пользователям в публичный канал

## Верификация перед завершением
Протестируй slash-команды, `defer()` на медленной операции, отсутствие прав и перезапуск с persistent buttons.
