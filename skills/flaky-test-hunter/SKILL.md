# Flaky Test Hunter

Систематическая охота на плавающие тесты: изоляция состояния, детерминизация времени/портов/случайности и проверка 20-кратным прогоном.

## Когда применять
- Тесты падают случайно в CI, при параллельном запуске или при смене порядка выполнения
- Необходимость убрать хрупкие `sleep()` и гонки из тестового сьюта

## Рабочий протокол
1. Воспроизведи флак локально: прогони тест в цикле 20–50 раз под CPU-нагрузкой и с рандомизацией порядка.
2. Классифицируй причину: фиксированное время/таймзона, общий temp-файл/порт/БД, гонка анимации/сети, утечка глобального состояния, нефиксированный RNG seed.
3. Замени все жёсткие `sleep(N)` на явное ожидание условия (polling assertion, event promise, locator auto-wait).
4. Выделяй уникальный `mkdtemp`, порт `0` (ephemeral OS port) и изолированную транзакцию/БД на каждый тест.
5. Инжектируй часы (`fake timers` / `freezegun`) и фиксируй seed генераторов случайных чисел.

## Чеклист качества
- [ ] Каждый тест проходит самостоятельно, в обратном порядке и в параллели (`-n auto`)
- [ ] В коде теста нет жёстких `sleep`/`setTimeout` для ожидания асинхронных событий
- [ ] После фикса тест стабильно проходит >= 20 последовательных прогонов подряд

## Антипаттерны (чего избегать)
- Просто увеличить `sleep(500)` до `sleep(5000)` или повесить `retry: 3` вместо устранения гонки
- Использовать жёстко заданный порт (например `8080`) в параллельных тестах

## Верификация перед завершением
Выполни 20-кратный стресс-прогон исправленного теста в параллельном режиме — 20/20 зелёных.
