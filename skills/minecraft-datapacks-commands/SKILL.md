# Minecraft Datapacks Commands

Разработка датапаков Minecraft 1.21+: актуальный `pack_format`, компонентный формат предметов (Data Components), макросы, предикаты и минимум тик-нагрузки.

## Когда применять
- Создание датапаков, `.mcfunction`, таблиц лута, рецептов, достижений и предикатов под Minecraft 1.21+
- Миграция старых NBT-команд на современный синтаксис Data Components (`item[custom_name=...]`) и имена папок (`function/`, `loot_table/`)

## Рабочий протокол
1. Учитывай изменения 1.21+: папки во множественном числе переименованы в единственное (`function`, `loot_table`, `recipe`, `predicate`, `item_modifier`, `advancement`), а предметы используют Data Components вместо старого `{tag:{}}`.
2. Минимизируй работу в `#minecraft:tick`: используй advancement-триггеры, `schedule function` и предикаты вместо ежетикового `execute as @e` по всему миру.
3. Избегай дорогого `nbt={...}` в селекторах на каждый тик — помечай сущности тегами (`tag`) и `scoreboard`.
4. Используй собственный уникальный namespace (`my_pack:`) для всех функций, скорбордов и хранилищ (`storage`), чтобы не конфликтовать с другими датапаками.
5. Проверяй JSON-файлы и логи загрузки сервера на ошибки валидации датапака.

## Чеклист качества
- [ ] `pack.mcmeta` имеет корректный `pack_format` под целевую версию 1.21.x
- [ ] Все JSON (рецепты, лут-таблицы, предикаты) валидны и лежат в правильных 1.21+ директориях
- [ ] Нет тяжёлых `@e[nbt=...]` проверок в тик-функции

## Антипаттерны (чего избегать)
- Писать старые пути `functions/` и старый NBT `{display:{Name:...}}` в датапаке под 1.21+
- Сканировать все сущности мира каждый тик без фильтров `type`, `distance`, `tag`

## Верификация перед завершением
Провалидируй JSON всех файлов и загрузи датапак через `/reload` без ошибок в логе.
