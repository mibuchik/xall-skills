# MCP Server Builder

Создание надёжных MCP-серверов (Python/TypeScript): чистые схемы инструментов, stdio JSON-RPC без мусора в stdout, таймауты и безопасные права.

## Когда применять
- Разработка нового MCP-сервера для подключения локальных инструментов, БД или API к AI-клиентам
- Отладка обрывов stdio JSON-RPC, ошибок схем и многошаговых tool calls

## Рабочий протокол
1. Проектируй инструменты под намерения пользователя (высокоуровневые операции с понятными аргументами), а не 1-в-1 обёртку над 50 сырыми REST-методами.
2. В stdio MCP-сервере НИКОГДА не пиши логи в `stdout` — только чистые JSON-RPC фреймы в `stdout`, все логи строго в `stderr`.
3. Описывай `inputSchema` максимально точно (типы, enum, описания, обязательные поля) и возвращай структурированные, компактные ответы с обрезкой гигантских выводов.
4. Устанавливай таймауты, валидацию путей и принцип минимальных привилегий для каждого инструмента.
5. Покрой сервер интеграционным тестом: `initialize` -> `tools/list` -> `tools/call` (успех и контролируемая ошибка `isError: true`).

## Чеклист качества
- [ ] В `stdout` не попадает ни одного `print()`/`console.log()` кроме JSON-RPC сообщений
- [ ] Инструменты возвращают понятную ошибку с подсказкой по исправлению аргументов вместо падения процесса
- [ ] Сервер корректно завершается при закрытии `stdin` (EOF)

## Антипаттерны (чего избегать)
- Возвращать 500 KB сырого JSON в одном `tool_result`, мгновенно забивая контекст модели
- Логировать дебаг-строки в `stdout` и ломать JSON-RPC парсер хоста

## Верификация перед завершением
Прогони тестовый stdio-клиент (`initialize` + `tools/list` + `tools/call`) и проверь чистый выход при EOF.
