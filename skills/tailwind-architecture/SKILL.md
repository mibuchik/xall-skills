# Tailwind Architecture

Чистая архитектура Tailwind CSS v4: `@theme` токены, типобезопасные варианты (`cva`/`tailwind-merge`), отсутствие «супа из классов» и малый бандл.

## Когда применять
- Проекты на Tailwind CSS v3/v4, настройка дизайн-токенов и переиспользуемых UI-примитивов
- Рефакторинг дублирующихся длинных строк утилитарных классов

## Рабочий протокол
1. Определи дизайн-токены через `@theme` (v4) или `theme.extend` поверх CSS-переменных, чтобы смена темы работала мгновенно.
2. Инкапсулируй повторяющиеся паттерны (Button, Badge, Card, Input) в тонкие компоненты с `cva` и `cn()` (`clsx` + `tailwind-merge`).
3. Никогда не собирай имена классов динамической конкатенацией (`bg-${color}-500`) — используй статические мапы вариантов для tree-shaking.
4. Группируй классы логически: layout -> spacing -> typography -> colors -> states/transitions.
5. Минимизируй `@apply` — используй его только для сторонних контентных областей вроде `.prose`.

## Чеклист качества
- [ ] Нет динамически склеенных utility-классов, которые вырежет JIT-сканер
- [ ] Итоговый CSS-бандл компактен и не содержит неиспользуемых утилит
- [ ] Внешний `className` проп безопасно переопределяет базовые классы через `twMerge`

## Антипаттерны (чего избегать)
- Копировать 25 одинаковых классов на каждую кнопку вместо компонента `<Button variant='...'>`
- Злоупотреблять произвольными значениями `[#1a1b1c]` и `[13.5px]` вместо токенов шкалы

## Верификация перед завершением
Собери production-бандл, проверь размер сгенерированного CSS и отсутствие пропавших классов.
