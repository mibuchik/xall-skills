# React 19 Patterns

Современные паттерны React 19: чистый поток данных, устранение лишних useEffect, Actions/useTransition, ключи сброса и стабильность рендеров.

## Когда применять
- Разработка и ревью компонентов на React 19 (веб, Electron, SPA, SSR)
- Устранение багов с гонками в эффектах, лишних перерендеров и рассинхронизации стейта

## Рабочий протокол
1. Выводи производные значения прямо при рендере (`const filtered = ...`), не дублируй их в `useState` + `useEffect`.
2. Сбрасывай внутреннее состояние компонента при смене сущности через `key={entityId}` вместо каскада `useEffect`.
3. Используй `useTransition` / Actions для неблокирующих обновлений интерфейса и всегда отменяй устаревшие асинхронные запросы в cleanup (`cancelled` / `AbortController`).
4. Держи состояние максимально близко к месту использования; поднимай вверх только действительно разделяемые данные.
5. Мемоизируй (`useMemo`/`useCallback`) осознанно — там, где есть тяжёлые вычисления или стабильность ссылок для эффектов/больших списков.

## Чеклист качества
- [ ] Каждый `useEffect` синхронизирует с внешней системой (DOM, IPC, сеть, таймер) и имеет cleanup
- [ ] Списки используют стабильные ID в `key`, а не индекс массива при перестановках/удалениях
- [ ] Нет мутаций props/state на месте и нет утечек подписок при unmount

## Антипаттерны (чего избегать)
- Цепочки `useEffect`, вызывающие друг друга и провоцирующие двойные рендеры и мигание UI
- Вызов `setState` без проверки отмены после завершения `async`-эффекта

## Верификация перед завершением
Запусти `tsc --noEmit`, тесты компонентов и проверь поведение в `React.StrictMode` (двойной mount/cleanup).
