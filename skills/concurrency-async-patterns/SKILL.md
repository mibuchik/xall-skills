# Concurrency Async Patterns

Безопасная конкурентность и асинхронность: structured concurrency, отмена (AbortSignal/Cancellation), backpressure и защита от race conditions.

## Когда применять
- Проектирование и отладка async/await, потоков, воркеров, очередей, стримов и блокировок
- Устранение гонок данных, deadlock, утечек задач и неконтролируемого параллелизма

## Рабочий протокол
1. Ограничивай параллелизм явно (семафор / worker pool / bounded queue), никогда не запускай неограниченный `Promise.all` или тысячи потоков на внешний ввод.
2. Прокидывай токен отмены (`AbortSignal`, `context.Context`, `asyncio.CancelledError`) во все I/O-вызовы и освобождай ресурсы строго в `finally` / `defer`.
3. Устанавливай фиксированный порядок захвата нескольких блокировок, чтобы структурно исключить deadlock.
4. Избегай check-then-act без атомарности: используй CAS, уникальные индексы БД или транзакционные блокировки.
5. Проверяй backpressure при стриминге: производитель обязан замедляться, когда потребитель не успевает читать.

## Чеклист качества
- [ ] Нет забытых фоновых задач без родительского жизненного цикла и обработчика ошибок
- [ ] При отмене запроса дочерние процессы, сокеты и файловые дескрипторы закрываются чисто
- [ ] Синхронные CPU-тяжёлые операции вынесены из event loop / UI-потока

## Антипаттерны (чего избегать)
- Смешивать блокирующий I/O внутри async event loop
- Глотать `CancelledError` / `AbortError` или оставлять незавершённые промисы без обработки

## Верификация перед завершением
Прогони стресс-тест с конкурентными запросами, принудительной отменой на полпути и race-детектором (`-race`, `pytest-asyncio`).
