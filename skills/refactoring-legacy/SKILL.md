# Refactoring Legacy

Пошаговый безопасный рефакторинг легаси-кода через characterization-тесты, strangler-fig и малые обратимые коммиты.

## Когда применять
- Рефакторинг старых монолитных модулей с высокой связностью и слабым покрытием тестами
- Замена устаревших API, распутывание циклических импортов и god-объектов

## Рабочий протокол
1. Зафиксируй текущее внешнее поведение characterization-тестами (golden snapshots / интеграционные тесты) ДО первого изменения логики.
2. Нарисуй карту входящих и исходящих зависимостей модуля (`rg`, граф вызовов), чтобы выделить безопасный шов (seam).
3. Применяй паттерн Strangler Fig: введи новый чистый интерфейс рядом со старым, переключи потребителей по одному, удали старый код в конце.
4. Разделяй структурные правки (переименования, переносы) и поведенческие изменения на разные коммиты.
5. После каждого шага прогоняй typecheck, линтер и characterization-тесты — никакой «большой переписки вслепую».

## Чеклист качества
- [ ] Внешний контракт (сигнатуры, коды ошибок, сериализация) сохранён либо задокументирован breaking change
- [ ] Удалены мёртвые ветки, временные адаптеры и неиспользуемые импорты
- [ ] Дифф читается линейно без перемешивания форматирования и логических правок

## Антипаттерны (чего избегать)
- Переписывать модуль с нуля без тестов на текущее поведение и граничные случаи
- Одновременно менять бизнес-логику, переименовывать файлы и менять форматирование

## Верификация перед завершением
Запусти тесты до и после каждого микрошага, проверь `git diff --stat` и статический анализатор.
