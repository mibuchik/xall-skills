# Performance Profiling

Оптимизация производительности по измерениям: профилирование CPU/IO flamegraph, p50/p95/p99 и устранение реальных узких мест без гаданий.

## Когда применять
- Медленный отклик API, лаги интерфейса, высокое потребление CPU или долгие сборки
- Запрос «ускорь это» — оптимизация строго на основе профилей и замеров

## Рабочий протокол
1. Сними воспроизводимый baseline: замерь p50/p95/p99 latency, throughput и CPU/IO до любых правок.
2. Собери профиль (flamegraph): `py-spy` / `cProfile` (Python), `node --cpu-prof` / Chrome DevTools (JS), `perf` / `pprof` (Go/Rust/C++).
3. Найди топ-1–3 горячих пути (закон Амдала): алгоритмическая сложность O(N^2), N+1 запросы, лишние сериализации/аллокации, блокирующий I/O.
4. Внеси ровно одну целевую оптимизацию за шаг и перемерь на том же бенчмарке.
5. Зафиксируй результат «до / после» числами и добавь регрессионный бенчмарк или лимит бюджета.

## Чеклист качества
- [ ] Есть численный замер «до» и «после» на идентичной нагрузке и железе
- [ ] Оптимизация не сломала корректность, читаемость и обработку краевых случаев
- [ ] Устранено корневое узкое место, а не микрооптимизация холодного пути

## Антипаттерны (чего избегать)
- Оптимизировать «на глаз» без профилировщика и базового замера
- Оценивать производительность только по среднему (`avg`), игнорируя хвост `p95`/`p99`

## Верификация перед завершением
Сравни профиль и метрики до/после; прогони полный набор тестов корректности.
