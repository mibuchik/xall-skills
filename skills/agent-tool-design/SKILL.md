# Agent Tool Design

Проектирование инструментов и циклов AI-агентов: идемпотентные контракты, защита от зацикливания, делегирование субагентам и бюджеты контекста.

## Когда применять
- Проектирование agent loop, набора инструментов (tools), субагентных протоколов и guardrails
- Устранение зацикливаний агента, переполнения контекста и опасных вызовов

## Рабочий протокол
1. Делай инструменты с короткими предсказуемыми контрактами, внятным описанием «когда использовать / когда НЕ использовать» и полезными сообщениями об ошибках.
2. Ограничивай размер вывода каждого инструмента (head/tail + указание общего числа строк/байт), чтобы модель сама запрашивала нужный диапазон.
3. Вводи защитные лимиты цикла: `max_turns`, детектор повторяющихся одинаковых вызовов, подтверждение деструктивных действий.
4. Для параллельной работы делегируй независимые куски субагентам с полным самодостаточным контекстом и непересекающимися областями файлов.
5. Логируй полную траекторию tool calls + latency + токены для последующего разбора сбоев.

## Чеклист качества
- [ ] При ошибке аргументов инструмент подсказывает модели валидные значения/пути
- [ ] Агент не тратит шаги на бессмысленный polling — использует реактивные уведомления или блокирующий результат
- [ ] Деструктивные действия требуют явного флага или подтверждения пользователя

## Антипаттерны (чего избегать)
- Давать агенту 40 пересекающихся инструментов с расплывчатыми описаниями
- Не ограничивать глубину рекурсии и число шагов в агентном цикле

## Верификация перед завершением
Протестируй траекторию на 5–10 типовых и краевых сценариях (ошибка инструмента, большой вывод, отмена).
